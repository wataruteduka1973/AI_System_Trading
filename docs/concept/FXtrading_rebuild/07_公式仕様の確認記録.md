# 公式仕様の確認記録

**最終確認日: 2026-08-16**

外部サービスの提供商品、銘柄、注文種別、制限は変更される可能性がある。本記録は設計根拠であり、アプリケーションは接続時および定期的にAPIから実際のcapabilitiesを取得して再確認する。

確認事項:

- MarketOrderRequestとLimitOrderRequestが定義されている。
- Market注文はFOK/IOC、Limit注文は価格と有効期間を扱う。
- stop-loss、take-profit、guaranteed stop-loss、trailing stop-loss等の関連注文が定義されている。
- 実際に利用可能な商品、精度、保証ストップ対応等は接続した口座のAPI応答から判定する。
- トークンからアクセス可能な口座一覧と各口座詳細をAPIで取得できる。
- 口座詳細にはhedgingEnabled、marginRate、marginAvailable、marginCallPercent、marginCloseoutPercent、保証ストップモード等が含まれる。
- practice/liveは接続先endpointが異なるため、アプリでも別接続として管理する。
- アプリは利用口座を選べるが、OANDAが持つ口座方式そのものを任意に変換できるわけではない。
- OANDAは各open tradeへのstop-loss設定とmargin状態の継続監視をリスク低減策として案内している。
- OANDA教育資料には1% risk ruleが紹介される一方、stop位置はリスク管理と戦略等の複数要因を考慮すべきとされている。このため本設計では1%を普遍的推奨値とはせず、初期値を0.5%へ保守化した。
- stop-lossは指定価格での約定を保証せず、gapや市場再開時には超過損失が生じ得る。
- GET /v3/accounts/{accountID}/pricing はClientPriceの配列を返す。bids/asksは各々PriceBucket(price, liquidity)の配列、closeoutBid/closeoutAskはポジション強制決済時専用の単一価格。bid/askの実測値をAPIから取得できる唯一の同期RESTエンドポイントである。
- GET /v3/accounts/{accountID}/pricing/stream はClientPrice(type="PRICE")を最大4件/秒/instrument(250ms間隔で間引き)で配信し、約5秒毎にPricingHeartbeatを送る。接続ごとに250ms窓のalignmentが異なるため、複数接続が同時刻に必ず同じ価格を受信するとは限らないとドキュメントに明記されている。
- GET /v3/accounts/{accountID}/instruments/{instrument}/candles のpriceパラメータ(PricingComponent型)は"M"(mid)/"B"(bid)/"A"(ask)の任意組み合わせ文字列(default="M")。レスポンスのCandlestickオブジェクトはbid/ask/midをそれぞれCandlestickData(o/h/l/c)として個別フィールドで返す。
- pricing/pricing-stream/candlesいずれのエンドポイントもページHTML内に「120 requests per second」という記述があるが、HTMLコメントとして無効化されておりドキュメント上には表示されない。公式に公開されたレート制限の記載は現時点で確認できなかった。
- `app/market_data/infrastructure/oanda_stream.py` が接続しているoandapyV20 PricingStreamは上記pricing/streamと同一のClientPrice(type="PRICE")オブジェクトを受信しており、`parse_price_tick`はpayload["bids"][0]["price"]とpayload["asks"][0]["price"]から直接bid/askを取得できている。現状は`mid = (bid+ask)/2`を計算した直後にbid/askを破棄し、`OandaPriceTick`にはmidのみを保持している。

- [Binance Spot REST API — exchangeInfo](https://developers.binance.info/en/docs/catalog/core-trading-spot-trading/api/rest-api)

- [Spot Testnet FAQ](https://testnet.binance.vision)
- [Binance dev forum: margin testnet question (1)](https://dev.binance.vision/t/is-there-a-testnet-for-margin-trading/16770)
- [Binance dev forum: margin testnet question (2)](https://dev.binance.vision/t/what-is-the-base-url-for-the-binance-margin-testnet/10721)

確認事項:

- `/api/v3/exchangeInfo` が取引中のsymbol、orderTypes、価格・数量filter、permissionsを返す。
- MARKET/LIMITを含む注文種別は銘柄ごとの応答を正本とする。
- `BTCJPY` を設定値だけで利用可能と仮定せず、接続先のexchangeInfoで `status=TRADING`、SPOT権限、必要なorderTypesを確認する。
- 初期版はSpot Testnetまたはpaperから検証し、margin・leveraged・derivativesを拒否する。
- **2026-09-20追加**: Margin取引(`/sapi/v1/margin/*`)専用のTestnetは公式には存在しない。Spot Testnet(`testnet.binance.vision`)は`/api/*`のみ対応で、`/sapi/*`は非対応とBinance開発者フォーラムでスタッフが複数回明言している(上記フォーラムリンク2件)。サードパーティのクライアントライブラリにMargin Testnet対応を謳う記述があるが、公式見解と矛盾しており真偽未確認。
- Margin発注は`POST /sapi/v1/margin/order`(Spotの`/api/v3/order`とは別)。認証は同じHMAC署名だが、APIキーにMargin取引権限の追加付与が必要。
- 借入・返済は`POST /sapi/v1/margin/borrow-repay`、金利履歴は`GET /sapi/v1/margin/interestRateHistory`/`interestHistory`、強制決済履歴は`GET /sapi/v1/margin/forceLiquidationRec`。
- リスク閾値は`GET /sapi/v1/margin/tradeCoeff`が`normalBar`/`marginCallBar`/`forceLiquidationBar`(応答例: 1.5/1.3/1.1)を返す。パラメータは`timestamp`/`recvWindow`のみで銘柄・VIPレベル指定は無く、構造上はアカウント単位の値。ただしVIPレベル依存の有無はドキュメント上明記が無く未確認。`marginLevel`(`GET /sapi/v1/margin/account`)とこれらのバーの数値的な対応関係(同一スケールで直接比較可能かどうか)も、ドキュメント上に明記された式・実例が見つからず未確認。
- Cross MarginとIsolated Marginはエンドポイント体系が別物(`/sapi/v1/margin/account` vs `/sapi/v1/margin/isolated/account`等)。`tradeCoeff`はCross Margin向けエンドポイント一覧に分類されており、Isolated向けの同等エンドポイントは見つからなかった(ただしこれはURL命名規則からの推測であり、ドキュメントの明示的な記述ではない)。

## Hugging Face Hub

- [Hub API endpoints](https://huggingface.co/docs/hub/en/api)
- [Hub security](https://huggingface.co/docs/hub/security)
- [Pickle scanning](https://huggingface.co/docs/hub/security-pickle)
- [Safe serialization](https://huggingface.co/docs/huggingface_hub/package_reference/serialization)

確認事項:

- Hub APIと公式クライアントでモデルメタデータを検索できる。
- Hubはマルウェア・pickle等のscan機能を提供するが、scanは完全な安全保証ではない。
- pickleはロード時に任意コード実行へつながる危険があり、safetensorsが推奨される。
- 本アプリではHubのscanだけに依存せず、safetensors限定、revision固定、checksum、隔離、ライセンス審査、独自評価を必須とする。
