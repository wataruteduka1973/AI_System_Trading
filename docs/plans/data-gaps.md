# 欠損データ画面(FR-UI-10)

状態: 実装済み(2026-10-09)。FR-UI-10「欠損範囲、影響、補完進捗、再検証結果を確認し、手動再試行できる」。フロントエンドの視認性向上・仕様対応の第5弾。

## 前提(調べたこと)

- `market_data_gap` の表と ORM は既にあり、検知も動いていた。Worker の補完の完了時と、公開履歴の取り込み時に `persist_internal_gaps` が欠損を記録し、後の確認で埋まっていれば `resolved` にする。
  状態は `open`(要対応)・`ignored`(取引所の元データにも無い足として、意図的に無視)・`resolved`。**読む API も画面も無かった。**
- ローカル DB には277件: 無視が273件(公開履歴の、2017〜2023年の取引所メンテナンス等)、要対応が4件(BTCJPY・Binance Testnet の 2026-09-07〜09 の約40時間。1m・1h・4h・1d)。
- `backfill_job.gap_id` の列はあるが、使われていなかった(0件)。既存の補完 `POST /candle-backfills` は「何日分」の指定で、欠損を狙えない。
- 公開履歴(`binance_public`)の欠損は、接続を持たないため、補完のジョブを作れない(再取得は公開履歴の取り込み)。

## 追加したもの

- **API**(`app/api/routes/market_data_gaps.py`、`app/market_data/application/gap_reports.py`):
  - `GET /workspaces/{id}/market-data-gaps`: 状態(複数)・銘柄・時間足で絞り込み、新しい範囲から。1ページ50件(最大200)、`limit` と `offset`。
    各欠損に、範囲・欠けている足の数・状態・検知時刻、**最新の補完ジョブ**(状態・エラー・再検証の結果)、**影響するBot**(その銘柄で稼働中または一時停止のBot)、いま補完できるか(`can_backfill`)。
  - `GET /workspaces/{id}/market-data-gaps/summary`: 銘柄・時間足ごとの、要対応の件数と欠けている足の数・無視・解消済みの件数。欠けている足が多い順。
  - `POST /workspaces/{id}/market-data-gaps/{gap_id}/backfill`(Operator、202): その欠損の範囲を補完するジョブを登録する(`use_cases.enqueue_gap_backfill`)。
  - ワークスペースが見られるのは、他の市場データの読み取りと同じ条件(選択済みで検証済みの口座がある取引所の、有効な銘柄)の銘柄と、公開履歴。条件は `access.readable_instrument_ids` に一本化している。他のワークスペースの銘柄の欠損は見えず、補完もできない(409)。
- **画面**(`/workspaces/{id}/data-gaps`、ナビに「欠損データ」): 先頭に「要対応の欠損があります(N件、欠けている足は合計M本)」か「要対応の欠損はありません」、銘柄・時間足ごとの集計表、
  欠損のカード(銘柄・取引所・時間足・状態・範囲と長さ・欠けている足・影響するBot・補完の進捗と再検証の結果・「この欠損を補完」「補完を再試行」)。
  既定は要対応だけで、「無視した欠損も表示」「解消済みも表示」で切り替える(件数は集計に常に出る)。補完が動いている間は5秒、それ以外は60秒ごとに更新する。
  読めないときは、空の一覧や「問題なし」ではなく、エラーを出す。

## 決めたこと

- **補完は、欠損の範囲を1足ぶん広げた期間のジョブ**(`gap_id` つき、手動)。前後の保存済みの足が窓に入るので、完了時の再検証(`persist_internal_gaps`)が、埋まった欠損を `resolved` にできる。
  既存の重複チェック(同じ銘柄・時間足で、待機中・実行中のジョブと期間が重なる場合は拒否)も使う。1年を超える範囲は拒否する。
- **再検証の結果は、ジョブの `validation_result` から読む**: 取引所から受信した本数、追加した本数、そして欠損が `resolved` になったか。完了したのに `open` のままなら、「取引所にもこの範囲の足が無い可能性がある
  (Binance Testnet は定期的にリセットされる)」と正直に出す(補完を何度押しても埋まらないことがある)。
- **公開履歴の欠損には、補完ボタンを出さない**(理由を画面に書く)。`ignored` と `resolved` にも出さない。補完の権限(Operator 以上)が無い人には、ボタンの代わりに説明を出す。
- **影響の見せ方**: 欠損は時間足ごと、Bot は自分の時間足で判断する。どの足に穴が当たるかは主張せず、その銘柄で稼働中のBot名を出す。

## 未検証・限界

- 実際の補完(ジョブの登録から Worker の実行、`resolved` への遷移)は、ブラウザでは見ていない。登録したジョブを Worker が Binance Testnet で実行するため。PostgreSQL では登録までと、`validation_result` の読み取りを確認した。
  完了後の `resolved` は、既存の `persist_internal_gaps` の挙動(窓に収まる欠損を、埋まっていれば解消にする)に依る。
- 要対応の4件は、Binance Testnet のリセットで、取引所側にも足が無い可能性が高い。補完しても埋まらず `open` のまま残りうる(画面は、その旨を出す)。
- 公開履歴の欠損の再取得は、この画面からはできない。
- 影響するBotは銘柄単位で、時間足は見ない。
