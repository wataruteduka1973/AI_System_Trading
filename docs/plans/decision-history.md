# 判断の履歴(Botが、なぜ取引したか・しなかったか)

状態: 実装済み(2026-10-12)。取引の見える化の第2弾(第1弾: `trade-history.md`、第3弾: チャートへの重ね表示)。

## なぜ

承認済みの戦略(4h足のDonchian)は、ほとんどの足で何もしない。「取引が無い」ときに、それが正常(シグナルが出ていない)なのか、リスク判定が拒否しているのか、取引停止(halt)が止めているのか、
Botが一時停止なのかを、画面から追えなかった。しかも、ローカルでは、売りのシグナルのほとんどが「Binance は空売りできない」で拒否されていて(`binance_no_short`)、それは `risk_decision` に残っていたが、見る手段が無かった。

## 記録されているもの(新しい保存は無い)

`bot_evaluation` が、足が確定するたびに次を記録する: `signal`(buy / sell / hold と、戦略の `rationale`)、新規のシグナルに対する `risk_decision`(`rule_results` に、各検査と通ったか)、
発注した新規の `order_intent` と注文・約定、反対のシグナルで建玉を決済したときの監査ログ(`dote_gate.close_only`)、そして `trading_halt`。

## 追加したもの

- **API**(読み取りのみ、ワークスペースのメンバーなら誰でも): `GET /workspaces/{id}/bots/{bot_id}/decisions`(`app/trading/application/decision_history.py`)。
  Botが評価した足ごとに、シグナル・**結果**・リスク判定・通らなかった検査(数値つき)・発注した注文と約定を新しい順に返す。絞り込みは、結果(複数)と期間。
  100件ずつ(最大200)、`before` + `before_id` の keyset(`created_at`, `id`)で古い方へ。期間全体の**内訳**(評価回数と結果ごとの数)と、その期間に重なるBotの**取引停止(halt)**(Bot・口座・ワークスペースのもの)も返す。
  他のワークスペースのBotは 404。
- **結果の決め方**(`derive_outcome`): `hold`(戦略が何も求めなかった)/ `ordered`(発注した: 注文意図がある)/ `closed`(反対のシグナルで建玉を決済した。決済は新規ではないのでリスク判定は無い)/
  `denied`(リスク判定が拒否)/ `halted`(リスク判定は許可したが、取引停止が新規を止めた)/ `paused`(何も記録が無い売買のシグナル: Botが一時停止中で、決済はできるが新規はしない)。
- **画面**(`/workspaces/{id}/decisions`、ナビに「判断の履歴」): Bot と期間を選ぶ。
  - **内訳の棒**: 結果ごとの割合(色)と、凡例の回数。
  - **時系列の帯**: 評価1回につき1マス(左が古い)を、結果の色で並べ、その下に、新規が止まっていた(halt)足を印す帯。マスを押すと、下のその足の説明が開く。
  - **一覧**: 足ごとに、結果・シグナル・**理由を1文で**(例: 「売りのシグナルが出ましたが、リスク判定で拒否しました — 空売りは不可(Binance は買いのみで、売りは決済のときだけ)」)。
    「詳細」で、評価した時刻・足の開始・戦略・リスク判定・通らなかった検査の数値・戦略の根拠(rationale)。
  - 「取引しなかった理由だけ見る」(拒否・停止中・一時停止中)、結果ごとの絞り込み、期間(既定は直近30日)、「さらに古い判断を読み込む」。
  - 期間に重なる取引停止(halt)の一覧(範囲・原因・いつからいつまで)。

## 決めたこと

- **理由は、記録された事実から作る**。hold は、Donchian の売買の条件(直前N本の高値を上抜ける / 直前M本の安値を下抜ける)と終値を出す。拒否は、`rule_results` の通らなかった検査を日本語にする
  (`binance_no_short`、`per_trade_loss`、`daily_loss`、`consecutive_losses`、`data_delay`、`quantity_calculation` ほか)。停止中は、評価した時刻に効いていた halt の原因を名指しする。
  未知の検査名・原因コードは、そのまま出す(隠さない)。
- 結果の判定と内訳は、**軽い行**(結果の判定に要る列だけ)で期間全体を読み、リスク判定の `rule_results`(大きい)は、表示するページの分だけ読む。Botは1台、足は4時間ごとなので、期間全体の読み込みは小さい。
- halt の帯は、時刻の軸ではなく、評価の列に合わせる(評価のたびに、そのとき効いていた halt があるかを印す)。時間の間隔が不揃いでも、どの判断のときに止まっていたかが、そのまま読める。
- `warning` の halt は、何も止めないので、「止まっていた」とは数えない。

## 検証

- 実 PostgreSQL(捨て DB、確認後に削除): `test_decision_history_postgres.py` 8件。各結果(hold・拒否と通らなかった検査の数値・停止中・一時停止中)、発注した注文と約定、決済の判定、結果の絞り込みがページだけを絞り内訳は変えないこと、
  keyset のページ送り、期間、他のBotの判断が入らないこと、halt(Bot・口座・ワークスペースのものだけで、他のBot・他の口座のものと、期間より前に解除されたものは含まない)。
- 単体: `test_decision_history_api.py` 20件(結果の決め方の全組み合わせ、通らなかった検査、API)、`DecisionHistoryPanel.test.tsx` 17件(説明文、halt の時間判定、内訳・時系列・クリック・絞り込み・停止の一覧、クエリ、ページ送り、失敗)。
- ローカル DB・ブラウザ(実データ): btcusdt-4h-donchian-110-40 は「評価4回(hold 3、拒否 1)」で、拒否の足は「売りのシグナルが出ましたが、リスク判定で拒否しました」「空売りは不可(Binance は買いのみで、売りは決済のときだけ)」
  「判定: 絶対上限(hard limit)を超えた」。hold の足は「シグナルなし(終値 83,321.81)」と売買の条件。bnbusdt-4h-donchian は「発注 1・hold 6」で、
  発注の足は「買いを発注し、約定しました(20.953 @ 795.43)」(取引履歴と一致)。マスを押すとその足が選ばれ、「取引しなかった理由だけ見る」で、拒否の無いBotは0件と説明が出る。幅375pxでページが横にはみ出さない。

## 未検証・限界

- 取引停止(halt)で見送った足、一時停止中で見送った足、反対のシグナルで決済した足は、ローカル DB に無く、ブラウザでは見ていない(PostgreSQL と単体テストでは確認)。
- 損切り(`stop-`)による決済は、シグナルではないので、ここには出ない(取引履歴に「損切り」として出る)。
- 評価が記録されない(Worker が止まっている)間は、判断も無い。それは、システム状態とイベントログで見る。
- 一時停止中の見送りは、「記録が何も無い売買のシグナル」から推定する(その足の評価の時点のBotの状態は保存していない)。
