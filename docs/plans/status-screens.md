# システム状態・取引停止・通知の画面

状態: 実装済み(2026-10-07)。フロントエンドの「現在の実装に合わせた視認性の向上」の第1弾(利用者の選択: 取引状態の見える化)。

## なぜ

バックエンドは、システム状態API・取引停止(halt)・アプリ内通知・台帳不整合の停止まで実装済みだが、画面には緊急停止の表示しか無かった。
Worker が止まっても、連敗で口座が止まっても、台帳の不整合を検知しても、画面では何も分からなかった(FR-UI-01、FR-UI-11、通知の確認)。

## 追加したもの

- **システム状態**(`/workspaces/{id}/status`、ナビに追加): `GET .../system-status` を15秒ごとに読み、判定(正常 / 要確認)と、サーバーが作った日本語の問題一覧を先頭に出す。
  その下に、トレーディングWorker・市場データWorker(閾値つき)、通知の配信、Botの状態別の数、取引所接続(最後の検証の結果を日本語で)。
  状態を読めないときは、最後の「正常」を残さず、「正常とは言えません」と出す。
- **取引停止センター**(同じページ): 有効な halt を、原因(日本語)・範囲(Bot名・口座名)・いつから・その段階で止まるもの・解除のしかたの説明つきで一覧にする。
  解除ボタンは Owner にだけ出す。`emergency_stopped` は `/emergency-release`、それ以外は `/release`(連敗・ドローダウンのロックは1回で解除、他は1段ずつ)。
  台帳不整合の解除が 409 で断られたときは、サーバーの理由(まだ合わない項目)をそのまま見せる。
- **通知**(同じページ): アプリ内通知を新しい順に出し、未確認を目立たせ、1件ずつ、またはすべてを確認済みにできる。
- **全ページ共通**: ナビの「システム状態」に未確認通知の数(通知が無く問題がある間は `!`)を出し、問題や未確認の通知があれば、どのページでも先頭に「要確認」のバナー(最初の問題と残りの件数)を出す。
  システム状態のページ自体では出さない。
- 狭い画面(幅640px以下)のナビを、1列8段から2列にした。

## 決めたこと

- バックエンドは変えない。既存のAPIだけで作れる範囲に絞った。
- 解除の関門(台帳不整合の照合)はサーバー側にあり、画面は理由を見せるだけ。
- ポーリングは15秒(Bot管理の5秒より緩い)。状態は秒単位の画面ではない。
- 取引停止センターは、既存の Bot 管理の緊急停止の表示を置き換えていない(そちらは緊急停止の操作と一緒に使う)。

## 検証

- `vitest`(新規: システム状態、通知、取引停止センター、ナビとバナー、ルート。全105件成功)、`eslint`、`tsc -b`、`npm run build`。
- ブラウザ(ローカル、実データ): システム状態は、Worker 停止中(トレーディング 12 Bot・市場データ 7 購読が実際に止まっている)を「要確認」と出し、
  ナビのバッジは未確認の通知 2件、Bot管理ページにもバナーが出た。幅375pxで、ナビが2列になり、内容がはみ出さない。

## 未検証・限界

- 取引停止センターの「halt がある」状態は、ローカル DB に halt が無く、ブラウザでは見ていない(単体テストのみ)。
- 通知の確認ボタンは、ローカルの通知を変えてしまうため、ブラウザでは押していない(単体テストのみ)。
- 残高・建玉・損益の表示(FR-UI-01/12)は、API が無いので含めていない。Bot管理の見やすさ(同名の口座の区別など)は次の段階。
