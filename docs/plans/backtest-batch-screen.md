# 複数銘柄のバックテスト(画面)

状態: 実装済み(2026-10-08)。API は `backtest-batch.md`(実装済み)。フロントエンドの視認性向上・仕様対応の第3弾。

## 追加したもの

- **フォーム**: 「1銘柄」と「複数銘柄をまとめて比較」を切り替える。複数のときは、取引用と検証用(公開履歴)の銘柄をチェックボックスで選ぶ(最大12。
  上限に達したら、選んでいない銘柄は選べなくなる)。時間足・期間・初期資金・spread・walk-forward は1銘柄のときと共通。
  実行ボタンは「N銘柄を実行」。足の合計が30万本を超えると全体が断られること(対処: 期間を短く、時間足を大きく、銘柄を減らす)を、フォームに書いている。
- **結果の比較表**(`BatchResults.tsx`): 銘柄ごとに、最大DD・純損益・リターン・勝率・PF・取引数・足数。**最大DDを純損益より前**に置く(損をしないことを優先する方針)。
  純損益とリターンは符号と色(緑 / 赤)で区別する。並び順は「選んだ順」「最大DDが小さい順」「純損益が大きい順」(実行できなかった銘柄は常に最後)。
  walk-forward のときは、銘柄ごとに訓練・検証の2行。「詳細を見る」で、既存の実行の詳細(取引一覧・資産曲線)を開く。
- **失敗した銘柄**は、その行に理由(`no_candles` など、日本語の説明つき)を出し、他の銘柄の結果は隠さない。要求全体が断られた場合(`batch_too_large` の 422)は、
  銘柄ごとの本数つきのサーバーの理由を、そのままメッセージに出す。
- 「銘柄ごとに独立した実行で、資金は共有しない(ポートフォリオの成績ではない)」を、結果の説明に書いている。
- ついでに、既存の実行の一覧が、純損益を生の小数文字列(`112452.54127243902150288...`)のまま出していたのを、丸めて出すようにした。

## 決めたこと

- バックエンドは変えない(`POST /backtests/batch` は実装済み)。
- 結果は、その場の応答で見せる。一覧への保存済みの実行も、これまでどおり下に並ぶ(実行ごとに保存される)。
- 銘柄数の上限(12)は、サーバーの `MAX_BATCH_INSTRUMENTS` と同じ値を画面にも持つ。サーバー側が最終の判断で、画面は選ばせないだけ。
- 足の本数は画面では数えない(サーバーが実行前に数えて断る)。
