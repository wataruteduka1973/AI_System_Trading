# 複数インジケーターによるエントリーの絞り込み (confluence filters)

## 目的

4h donchian_55_20 / 損切りのみ(`docs/plans/rolling-walk-forward.md` の決済方針の比較で最良)を土台に、
複数のインジケーターがそろったときだけ買うことで、次の2点を改善できるか検証する。

- 後半ほど弱い(前半+65.1% → 後半+17.8%、直近24区間はベンチマーク未満)
- 最高値を更新できない期間が長い(最長990日)

方針は「大きな利益より損をしないこと」(許容最大DD 10%、同じ量の買い持ちより下落局面の損が小さく、
全期間でプラス)。

## 設計

### 絞り込み条件(買いにだけ適用、売りは絞らない)

事前に固定した3種類 × 選択肢 = 12通り。閾値は定番値に固定し、調整しない。

| 条件 | 選択肢 |
|---|---|
| トレンド | 使わない / 終値 > EMA(200) |
| ボラティリティ | 問わない / ATR(14)%が直近260本の中央値以下(落ち着き) / 中央値超(拡大) |
| 過熱 | 使わない / RSI(14) < 75 |

売りを絞らない理由は他の戦略と同じ(このエンジンでは反対シグナルが損切り以外の唯一の出口)。

### 条件の選び方(walk-forward内での選択)

各foldで、直前の訓練期間に12通りをすべてreplayし、スコアが最も高い条件を次の検証期間に使う。
スコアは損を避ける方針に合わせて `リターン − 2 × 最大DD`。同点なら候補の並び順で先のもの
(先頭は「絞り込みなし」)を選ぶ。

訓練期間は360日(90日から延長)。4h donchian_55_20は月1回程度しか取引しないため、90日では選択の
根拠にならない。比較対象(絞り込みなし、12通りの固定)も同じ360日/30日のfoldで評価する。

### 高速化

インジケーター(EMA200、ATR%とその260本中央値、RSI14)は全期間で一度だけ、各足までのデータだけを
使って順に計算し(look-aheadなし)、シグナル関数は足の `open_time` で引くだけにする。
12通り×約100 fold×(訓練+検証)を、各足でインジケーターを再計算すると数時間かかるため。

## 変更対象

- `app/trading/application/confluence_signal.py`(新規): インジケーター表の構築、絞り込み条件、
  donchian_55_20に条件を掛けるシグナル関数
- `app/trading/application/backtest_walk_forward.py`: 訓練期間で候補を選ぶ `run_selected_walk_forward`
- `app/trading/application/backtest_robustness.py`: 比較用の集計(`summarize_windows`)を共通化
- `scripts/evaluate_confluence.py`(新規): 研究用の比較スクリプト

## テスト

- インジケーター表: 各値がその足までのデータだけで決まる(未来の足を変えても値が変わらない)
- 条件: 各条件が買いだけを止め、売りは通す。表に値が無い足では買わない
- 選択: 訓練期間のスコアが最も高い候補が検証期間に使われる。同点は先頭。訓練と検証が重ならない

## 想定リスク

- 12通りから選ぶこと自体が過剰適合を生みうる。固定の12通りと並べ、選択が固定より良いかを確認する。
- 訓練期間の成績と次の30日の成績に関係が無ければ、選択はランダムと同じになる。
- 絞り込むほど取引が減り、統計的な判断が難しくなる。
