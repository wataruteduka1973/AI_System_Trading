# ワークスペースのシステム状態 API

状態: 実装済み(2026-10-07)。画面で表示する部分は未実装。

`GET /workspaces/{id}/system-status`(ワークスペースのメンバーなら誰でも)。Worker とその周りが「いま健康か」を1回の呼び出しで返す。
通知は「止まったとき1回」知らせるが、これは「いまどうか」を毎回答える。状態を見る画面(開発状態のページなど)が使う。

## 返すもの

- `overall`: `ok` / `attention`(`problems` が空でなければ `attention`)。`problems`: そのまま表示できる日本語の一覧。
- `trading_worker`: `ok` / `stalled` / `idle`(稼働中のBotが無い)。稼働中のBot数、最後の heartbeat からの秒数、止まっているBot名、閾値。
- `market_data_worker`: `ok` / `stalled` / `idle`(有効な購読が無い)。有効な購読数、停止(blocked)の数、遅れている数、最も遅れている秒数、閾値。
- `notifications`: 配信待ちの件数と最も古い待ち時間、直近7日に届けられなかった(`failed`)件数。ワークスペースの `SystemEvent` と `correlation_id` で結びつけた分だけ。
- `halts`: 有効な halt のレベル別の件数。`bots`: Bot の `actual_state` 別の件数。
- `connections`: 接続ごとの状態と、最後の検証の結果・時刻(秘密は含まない)。

`problems` に載るもの: トレーディングWorkerの停止、`failed` のBot、市場データWorkerの停止、停止した自動取得、有効な halt(`warning` は何も止めないので除く)、
5分以上配信されていない通知、届けられなかった通知。

## 決めたこと

- **アラートと同じ問い合わせ・同じ閾値**。`worker_watchdog`(トレーディング・市場データ)の検索を共通にし(`find_stalled_bots` / `find_overdue_subscriptions`)、
  アラートと状態が食い違わない。閾値は `TRADING_WORKER_STALE_SECONDS`(180秒)と `MARKET_DATA_WORKER_OVERDUE_SECONDS`(600秒)。
- **Workerに何も足さない**。すでにあるheartbeat・購読の期限・Outbox・haltを読むだけ。
- **`idle` は `ok` ではない**。何もしていない状態を、健康とは言わない。ただし問題でもない。

## 接続の認証失敗の定期確認は作らなかった(判断)

当初は「取引口座の接続を定期的に確かめて、認証失敗を通知する」ことを想定したが、次の理由で見送った。

- ペーパーの Bot は取引所に認証して注文しない(約定は自前のシミュレーション、価格は認証不要の公開API)。認証が必要なのは、Testnet/Practice のローソク足の取り込みだけで、
  そこで認証が失敗すれば、購読が止まり、すでに通知される(`market_data_stopped`、原因「取引所の認証に失敗」)。つまり、使っている接続の認証失敗は、すでに検知できている。
- 定期的に認証すると副作用が大きい。既存の検証は、失敗(通信失敗も含む)すると接続を `invalid` にし、アカウントの選択・Botの起動・データ取り込みを止める。
  一時的な通信エラーで止まるのは危険で、これを避けるには、検証の挙動自体を変える必要がある。
- OANDA は、トークンを発行できないため、認証失敗が既知(401)のまま。定期確認を足すと、解消するまで通知が出続ける。
- 代わりに、`connections` で最後の検証の結果を見られるようにした。**ローカルでは、OANDA の接続が `verified` のまま、最後の検証の結果が `authentication_failed`** になっている
  (以前の検証の食い違い。状態の更新の不整合で、今回は直していない)。

実取引(別プロジェクト)に進むときは、認証失敗を `all_trading_halted` にする(取引停止マトリクスの「API認証失敗」)が、ペーパーの範囲では要らない。

## 既知の制限

- 画面は未実装(API のみ)。
- 状態の再計算ごとにいくつかの問い合わせを実行する。画面が数秒ごとに呼ぶ想定なら問題ないが、大量に呼ぶ場合は間引く。
- 通知 Worker の停止そのもの(配信待ちが5分以上ある場合に出る)以外は、検知できない。
