# AI学習と外部モデル探索設計

## 1. 結論

AIモデルはアプリ内で学習できるようにする。加えて、外部の無料公開モデルを検索して候補化できるようにするが、「自動検索」と「自動採用」は分ける。

アプリが自動化してよい範囲は、メタデータ検索、形式・ライセンスの一次判定、隔離ダウンロード、checksum検証、互換性検査、共通評価までとする。実取引への配備には人の承認を必須とする。

## 2. 内製モデルの学習フロー

```mermaid
flowchart LR
    C["確定済みOHLCV"] --> D["Dataset Snapshot"]
    D --> Q["品質・リーク検査"]
    Q --> T["Training Job"]
    T --> E["Holdout Evaluation"]
    E --> B["手数料込みBacktest"]
    B --> P["Paper Observation"]
    P --> A["Owner Approval"]
    A --> R["Model Registry"]
    R --> X["停止中Botへ配備"]
```

### 学習データ

- OANDA `USD_JPY` とBinance `BTCJPY` を別モデルとして開始する。
- 市場間で特徴量スキーマ、取引時間、スプレッド、ボラティリティが異なるため、初期版では一つのモデルへ混在させない。
- ローソク足、spread、volumeが取得可能ならvolume、セッション情報、テクニカル派生値を候補とする。
- 欠損補完された区間はフラグを持たせ、品質基準を超える場合は学習対象から除外する。
- 正解ラベルは将来リターン等から作るが、予測時点より後の情報を特徴量へ含めない。

### 評価ゲート

精度だけでは採用しない。少なくとも以下を保存・比較する。

- PR-AUC、ROC-AUCまたは回帰誤差（タスクに応じる）
- 手数料、spread、slippage込みの損益
- 最大ドローダウン
- Profit Factor、勝率、取引回数
- 相場局面別の性能
- baseline（売買なし、単純ルール、前モデル）との差
- 時系列外検証とwalk-forward結果
- 推論時間、欠測耐性、モデルサイズ

## 3. 外部モデル探索

初期カタログ候補はHugging Face Hub APIとする。検索対象は時系列予測・分類モデルだが、金融用と書かれているだけで信用しない。

公開モデルの検索・取得が無料であっても、ライセンスが自由とは限らず、学習・評価・推論に必要なCPU/GPU、保存領域、通信には利用者側の費用が発生し得る。「無料」はモデル価格、利用許諾、計算費用を分けて画面表示する。

### 探索条件

- task/tagが時系列予測または互換タスク
- ライセンスが明記され、許可リストに含まれる
- safetensors形式が存在する
- revision/commitを固定できる
- モデルカード、入力仕様、学習データの説明が存在する
- 任意コード実行を要求しない
- 本アプリの特徴量・tensor shape・frameworkと互換または変換可能

### 擬似コード

```python
def discover_candidates(query, policy, catalog):
    metadata_items = catalog.search_metadata(query)
    candidates = []
    for item in metadata_items:
        if item.license not in policy.allowed_licenses:
            continue
        if not item.has_safetensors:
            continue
        if item.requires_remote_code:
            continue
        if not compatible_task(item.task, query.task):
            continue
        candidates.append(pin_revision_and_record_metadata(item))
    return rank_metadata_only(candidates, policy)
```

検索処理はモデルをimportしたり、リポジトリ内Pythonを実行したりしない。候補を選んだ後、別の隔離ジョブが固定revisionから許可ファイルだけを取得する。

## 4. 供給網セキュリティ

- `.pkl`、`.pickle`、`.pt`、`.pth`、実行可能ファイルを外部候補として拒否する。
- safetensors、JSON設定、Markdownモデルカード等の許可拡張子だけを取得する。
- `trust_remote_code` は常にfalse。
- revision、各ファイルSHA-256、取得日時、配布元、ライセンス本文を保存する。
- ダウンロードコンテナは秘密情報、取引API、取引DBへのアクセスを持たない。
- ファイル数、個別サイズ、総容量、展開サイズ、通信先を制限する。
- マルウェアscan結果だけを安全の保証とせず、非実行形式と隔離を主防御にする。
- モデル作者の公開スコアを採用判定に使わず、同一データで再評価する。

## 5. モデル状態

```text
discovered
  → quarantined
  → security_reviewed
  → compatible
  → evaluated
  → approved
  → paper_observation
  → deployable
  → deployed
  → retired / rejected
```

状態を飛ばすことはできない。`rejected` の理由はライセンス不明、危険形式、互換性なし、性能不足、ドリフト等のコードで保存する。

## 6. 自動ランキング

「高性能」は単一スコアにしない。候補ランキングは以下を別軸で表示する。

- 安全・来歴: license、revision固定、非実行形式、作者・モデルカード
- 互換性: task、入力形状、特徴量、framework、推論資源
- 検証性能: 本アプリのholdoutとbacktest
- 運用性能: 推論遅延、メモリ、モデルサイズ
- リスク: 最大DD、最悪期間、性能ばらつき、ドリフト

最低安全条件を満たさない候補は、性能に関係なくランキング対象外とする。

## 7. 学習・配備の安全性

- 学習とライブ推論は別ワーカー・別資源枠にする。
- 学習負荷が市場データ取得や注文処理を遅延させない。
- 配備は停止中Botにだけ行い、モデル版と特徴量版を原子的に切り替える。
- 直前の承認済み版へ即時ロールバック可能にする。
- 入力分布、予測比率、推論失敗率、損益、DDを監視する。
- ドリフトまたは異常検出時は `entry_halted` とし、自動で別モデルへ切り替えない。

## 8. 初期実装順

1. Dataset Snapshotと時系列分割
2. 単純なbaselineモデルとテクニカル戦略の比較
3. 学習ジョブ、評価、モデルレジストリ
4. paper配備と監視
5. Hugging Faceメタデータ検索
6. safetensors限定の隔離取込
7. 互換変換、共通評価、承認UI

外部モデル探索は便利だが、最初から必須経路にはしない。まず内製baselineで評価パイプライン自体の正しさを確立し、その同じパイプラインへ外部候補を通す。
