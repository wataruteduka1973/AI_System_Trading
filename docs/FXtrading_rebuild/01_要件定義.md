# 要件定義書（改訂版 0.5）

## 1. 目的

利用者が外貨FXと仮想通貨FXを同一アプリケーションで管理し、市場ごとに個別運転、同時運転、停止を選択できるようにする。市場データ、戦略シグナル、リスク判定、ペーパートレード結果を一つの画面で追跡し、安全に戦略を検証できるアプリケーションを新規に構築する。

成功とは、収益を保証することではなく、同じ入力と設定から再現可能な判断を行い、注文に至る全判断を監査でき、障害時に安全側へ停止できることである。

## 2. 利用者と権限

| ロール | 主な権限 |
|---|---|
| Owner | 接続先・秘密情報・実取引許可・利用者・全設定の管理 |
| Operator | Botの起動停止、緊急停止、ペーパー口座操作、履歴閲覧 |
| Viewer | ダッシュボードと履歴の閲覧のみ |
| System Worker | 市場データ取得、戦略評価、注文執行、集計 |

初期リリースを単一利用者とする場合も、データには `workspace_id` を持たせ、後の分離を可能にする。

## 3. 対象範囲

### MVPに含める

- ログインとロールベース認可
- 画面からの取引所・ブローカーAPI登録、権限確認、接続テスト、更新、無効化
- 外貨FXと仮想通貨FXの接続・口座・Botの個別管理と同時運転
- 市場、商品、銘柄、時間足の設定
- 市場データのリアルタイム取得と履歴補完
- OHLCVチャートとテクニカル指標表示
- バージョン管理された戦略設定
- シグナル生成と根拠の保存
- リスクルールの判定と拒否理由の保存
- ペーパー注文、約定、ポジション、残高、損益
- Botの起動、停止、緊急停止
- 運用イベントログ、監査ログ、ヘルス状態、通知
- バックテストジョブと結果比較
- ダッシュボード、接続管理、戦略作成、リスク設定、イベント検索等の操作画面

### MVP後

- 実注文
- 追加の取引所・ブローカーアダプター
- GNN/Transformer等、複数種類のモデル学習
- ニュースセンチメント
- 複数戦略・複数銘柄のポートフォリオ最適化
- モバイル通知、外部Webhook

### 対象外

- 収益または損失回避の保証
- 投資助言・顧客資産の受託管理
- 高頻度取引やマイクロ秒単位の執行
- 取引所そのものの台帳を置き換える会計機能

## 4. 機能要件

### アカウント・セキュリティ

- **FR-AUTH-01** 利用者は認証後のみアプリへアクセスできる。
- **FR-AUTH-02** 破壊的操作と実取引関連操作はOwnerのみ実行できる。
- **FR-AUTH-03** APIキーの秘密値は作成・更新時以外にAPIから返さない。
- **FR-AUTH-04** 重要操作は操作者、時刻、対象、変更前後、相関IDとともに監査記録へ残す。
- **FR-AUTH-05** 接続登録画面はAPIキー、秘密、口座ID等を一度だけ受け付け、登録後はマスク表示する。
- **FR-AUTH-06** 接続テストは認証成否、読取権限、取引権限、対象市場、口座種別を個別に表示する。
- **FR-AUTH-07** 出金権限を持つAPIキーは登録を拒否または重大警告とし、原則として取引・照会に必要な最小権限だけを許可する。
- **FR-AUTH-08** 初期利用者は単一Ownerとするが、第三者配布・販売に備えてworkspace単位のデータ・秘密・Bot分離を維持する。
- **FR-AUTH-09** 認証情報が未登録でも接続設定を `pending_credentials` として作成し、画面・仕様確認・非秘密設定を先に進められる。
- **FR-AUTH-10** OANDA/Binanceの秘密入力後にのみ検証・口座同期を開始し、秘密値をDB・ログ・イベントへ保存しない。

### 複数市場・接続

- **FR-MKT-01** 外貨FXと仮想通貨FXを同一workspaceへ登録できる。
- **FR-MKT-02** 市場接続、口座、Botは独立し、一方の障害や停止が他方を無条件に停止させない。
- **FR-MKT-03** 利用者は市場別またはBot別に、個別起動、個別停止、一括停止を実行できる。
- **FR-MKT-04** 同じ時間帯に複数市場・複数銘柄のBotを並行稼働できる。
- **FR-MKT-05** Spot、margin、perpetual、futures、FX spot等の商品種別を識別し、商品種別に適合しない注文を拒否する。
- **FR-MKT-06** レバレッジ、証拠金方式、建玉方向、強制決済条件を口座・商品単位で管理する。
- **FR-MKT-07** 初期外貨FX接続はOANDA v20、対象は `USD_JPY` とする。
- **FR-MKT-08** 初期仮想通貨接続はBinance、対象は接続先の `exchangeInfo` で取引可能と確認できた `BTCJPY` とする。
- **FR-MKT-09** Binance初期版はspot専用とし、margin、leveraged、perpetual、futures権限または注文を拒否する。
- **FR-MKT-10** 接続先で `BTCJPY` が利用不能な場合、代替銘柄へ暗黙変換せず、Bot作成を停止して利用者へ通知する。
- **FR-MKT-11** OANDAトークンでアクセス可能な全v20口座をAPIから列挙し、practice/live endpoint、通貨、hedgingEnabled、marginRate、MT4関連、保証ストップ能力を同期する。
- **FR-MKT-12** ユーザーは画面から利用口座を明示選択できる。複数口座を同一接続へ登録できる。
- **FR-MKT-13** 自動選択を使う場合は、practice優先、通貨、hedging可否、最小余力、live許可等を持つバージョン済み口座選択ポリシーに限定する。
- **FR-MKT-14** APIが返すhedgingEnabled等の口座属性をアプリ設定で偽装または上書きしない。希望方式の口座がなければ選択を失敗させる。
- **FR-MKT-15** practiceとliveは別接続として扱い、endpoint、秘密参照、利用許可、イベントを混在させない。
- **FR-MKT-16** v20 APIに公開されない旧式または非対応口座は対象外とし、画面に理由を表示する。

### 取引アルゴリズム

- **FR-ALG-01** 取引アルゴリズムを市場データ入力、特徴量、エントリー、エグジット、ポジションサイズ、注文方式、適用市場の集合として定義する。
- **FR-ALG-02** アルゴリズム定義は不変バージョンとし、作成者、根拠、checksum、コード版、対応市場を保存する。
- **FR-ALG-03** technicalアルゴリズムは全条件と計算値、ai_modelアルゴリズムはモデル版・特徴量版・閾値を保存し、判断を再現できる。
- **FR-ALG-04** アルゴリズムは静的検証、単体試験、履歴バックテスト、walk-forward、paper観測、承認を順に通過する。
- **FR-ALG-05** 未承認アルゴリズム、評価期限切れアルゴリズム、入力互換性のないアルゴリズムをBotへ配備できない。
- **FR-ALG-06** 稼働中アルゴリズムを直接編集せず、停止中Botへ新バージョンを原子的に配備する。
- **FR-ALG-07** 配備後は直前の承認版へロールバックできる。自動ロールバック条件も版管理する。
- **FR-ALG-08** live稼働中の自己改変・自動再学習・未承認モデルへの自動切替を禁止する。
- **FR-ALG-09** 同一市場・時間足で複数アルゴリズムを比較できるが、1 Botの注文決定責任を持つアルゴリズム版は常に一つとする。
- **FR-ALG-10** アルゴリズムの性能を損益だけでなくDD、注文頻度、slippage、相場局面、データ品質、安定性で監視する。
- **FR-ALG-11** アルゴリズム変更、承認、配備、停止、切戻しをイベントログと監査ログへ残す。
- **FR-ALG-12** アルゴリズムが出したシグナルをリスク管理が常に再判定し、アルゴリズム自身がリスク上限を迂回できない。

### 市場データ

- **FR-MD-01** 対象取引所からティックまたはティッカーを継続取得する。
- **FR-MD-02** ティッカーからOHLCVをUTC境界で集計する。
- **FR-MD-03** 1m、15m、1h、1dの履歴を取得できる。
- **FR-MD-04** 欠損、重複、未来時刻、異常価格を検出し、品質状態を記録する。
- **FR-MD-05** WebSocket切断時は再接続し、必要に応じてREST補完する。品質が回復するまで売買判断を停止する。
- **FR-MD-06** 同一取引所・銘柄・時間足・開始時刻のローソク足を一意にする。
- **FR-MD-07** 欠損検出時は範囲、原因、影響Botをイベント記録し、補完ジョブを自動または手動で開始できる。
- **FR-MD-08** 補完データを重複なくupsertし、補完後に連続性・OHLC整合性を再検証する。
- **FR-MD-09** 売買判断に必要な足が欠損しているBotだけを停止し、無関係な市場・Botは継続できる。

### 戦略モード

- **FR-ST-01** Botは `technical` または `ai_model` の戦略モードを必ず一つ選択する。
- **FR-ST-02** テクニカル指標モードはEMA、SMA、RSI、MACD、ボリンジャーバンド等の条件を組み合わせ、判定式を画面で設定できる。
- **FR-ST-03** シグナルごとに入力データ範囲、戦略版、判定値、理由を保存する。
- **FR-ST-04** 同じ確定足・戦略版・入力に対する評価を冪等にする。
- **FR-ST-05** 未確定足を売買判断へ使うか否かを戦略ごとに明示し、既定では使わない。
- **FR-ST-06** AIモデルモードは承認済みモデル版、特徴量スキーマ、判定閾値を固定して推論する。
- **FR-ST-07** AIモデルが未配置、不整合、期限切れ、推論失敗の場合はテクニカルモードへ暗黙に切り替えず、そのBotを停止する。
- **FR-ST-08** 各戦略版は対応する市場種別、商品種別、時間足、必要データ量を宣言する。
- **FR-ST-09** モード変更は稼働中に直接行わず、Bot停止後に新しい設定版として適用する。
- **FR-ST-10** 将来ハイブリッドモードを追加できる境界を持つが、MVPではAIとテクニカルを混合しない。

### リスク管理

- **FR-RISK-01** 注文前にデータ品質、最大ポジション、日次損失、ドローダウン、取引頻度を確認する。
- **FR-RISK-02** 各判定の許可・拒否、閾値、観測値、理由を保存する。
- **FR-RISK-03** 緊急停止中は新規注文を作らない。決済を許可するかはポリシーで指定する。
- **FR-RISK-04** ストップ条件は注文・ポジションと関連付け、プロセス再起動後も復元する。
- **FR-RISK-05** リスク設定変更は稼働中のBotへ即時反映せず、新しい設定版を明示的に適用する。
- **FR-RISK-06** 取引停止を `warning`、`entry_halted`、`all_trading_halted`、`emergency_stopped` の状態で管理する。
- **FR-RISK-07** 停止イベントには適用範囲、原因コード、観測値、閾値、自動解除可否、解除条件を保存する。
- **FR-RISK-08** `entry_halted` では新規建玉を禁止し、リスク低減の決済と注文取消は許可する。
- **FR-RISK-09** `all_trading_halted` では自動売買を止め、既存注文の取消とOwner承認済み緊急決済だけを許可する。
- **FR-RISK-10** `emergency_stopped` は自動解除せず、原因解消確認と権限者の手動解除を必要とする。
- **FR-RISK-11** 停止範囲はsystem、workspace、connection、account、bot、instrumentから選択できる。
- **FR-RISK-12** 証拠金維持率、レバレッジ、清算価格までの距離をFX商品向けリスク判定へ含める。
- **FR-RISK-13** 新規workspaceには `conservative-v1` リスクテンプレートを適用する。
- **FR-RISK-14** リスク値は画面で変更可能だが、変更は新しい不変版として保存し、差分、理由、操作者を記録する。
- **FR-RISK-15** 安全性を弱める変更は即時反映せず、確認画面、再認証、影響計算、Owner承認、Bot再起動を必要とする。
- **FR-RISK-16** 管理上限を超える設定は、通常UIでは保存できない。上限自体の変更は別のsystem policyとして扱う。
- **FR-RISK-17** ストップ距離は固定pipsだけでなくATR、spread、取引所最小距離を考慮して決める。
- **FR-RISK-18** 想定損失額から注文数量を逆算し、ストップを広げても1取引リスク率を超えないよう数量を減らす。
- **FR-RISK-19** ストップ注文は損失額を保証しない。gap、slippage、取引停止時の超過損失を別のstress lossとして表示する。
- **FR-RISK-20** OANDA口座のmarginCallPercent、marginCloseoutPercent、marginAvailableを監視し、アプリの警戒閾値をbroker強制決済より十分手前に置く。

### 注文・ペーパートレード

- **FR-ORD-01** シグナルと注文意図を分離し、リスク承認後のみ注文を生成する。
- **FR-ORD-02** 注文は `client_order_id` により重複送信を防止する。
- **FR-ORD-03** 注文、約定、手数料、ポジション、残高を別々に記録する。
- **FR-ORD-04** ペーパー約定はbid/ask、手数料、スリッページ、部分約定を設定可能にする。
- **FR-ORD-05** 注文状態は `pending → submitted → partially_filled → filled/cancelled/rejected/expired` として管理する。
- **FR-ORD-06** 外部取引所の状態と内部状態を定期照合し、不一致をアラートする。
- **FR-ORD-07** 実取引は既定で無効とし、環境・workspace・Botの三段階許可を必要とする。
- **FR-ORD-08** OANDA USD/JPYは成行注文と指値注文の買い・売りに対応する。
- **FR-ORD-09** Binance BTC/JPY spotは、接続時に `exchangeInfo` で許可を確認できた成行注文と指値注文に対応する。
- **FR-ORD-10** 成行注文には最大許容スリッページまたはprice boundを設定し、超過時は拒否または未約定とする。
- **FR-ORD-11** 新規建玉にはストップロスを必須化する。OANDAでは取引所側の保護注文を優先し、Binance spotではサーバー側監視の停止リスクを明示する。
- **FR-ORD-12** 指値注文には有効期限、最大未約定時間、価格乖離上限を設定し、期限後は取消する。
- **FR-ORD-13** 1注文、1日、口座、Botごとの最大損失・最大注文額を超える注文を拒否する。
- **FR-ORD-14** 初期リリースのpaper取引はOANDA/Binanceの実市場価格、spread、取引ルール、取引時間を取得して内部約定する。
- **FR-ORD-15** paper口座は外部注文endpointを呼べない専用adapterを使用し、接続キーに取引権限があっても注文を送信しない。
- **FR-ORD-16** paper約定では実市場のbid/ask、利用可能な板情報、手数料、slippage、注文filterを反映し、理想的なmid価格だけで約定しない。
- **FR-ORD-17** 外部市場データが利用不能な場合、架空価格へフォールバックせず該当Botを停止する。

### 画面・運用

- **FR-UI-01** ダッシュボードに接続状態、データ遅延、Bot状態、モード、残高、ポジション、当日損益を表示する。
- **FR-UI-02** チャートにOHLCV、選択指標、シグナル、注文、約定を重ねて表示する。
- **FR-UI-03** Botの起動・停止・緊急停止は結果が確認でき、二重操作でも安全である。
- **FR-UI-04** エラーは利用者向けの説明と追跡IDを表示し、内部例外や秘密値を表示しない。
- **FR-OPS-01** ワーカー、データ遅延、キュー、外部API、DBのヘルスを確認できる。
- **FR-UI-05** 市場切替ビューと統合ビューを提供し、外貨FX・仮想通貨FXの状態を並べて比較できる。
- **FR-UI-06** 接続ウィザードでプロバイダー、市場、口座、認証情報、権限、接続結果を段階的に設定できる。
- **FR-UI-07** テクニカル戦略ビルダーで指標、期間、比較演算子、AND/OR条件、売買条件を設定・検証できる。
- **FR-UI-08** AIモデル画面でモデル版、評価指標、学習期間、対応市場、特徴量、承認状態を確認できる。
- **FR-UI-09** イベントログ画面で時刻、重要度、カテゴリ、市場、Bot、相関ID、原因コードを検索・絞り込みできる。
- **FR-UI-10** 欠損データ画面で欠損範囲、影響、補完進捗、再検証結果を確認し、手動再試行できる。
- **FR-UI-11** 取引停止センターで現在の停止範囲、理由、許可される操作、解除条件、承認履歴を確認できる。
- **FR-UI-12** 注文、約定、ポジション、損益、証拠金状況を市場別・口座別・統合で表示する。
- **FR-UI-13** アルゴリズム画面で版、状態、入力、ルール、モデル、評価、変更差分、適用Botを確認できる。
- **FR-UI-14** リスク編集画面は各値の意味、現在値、初期値、許容範囲、推定注文量、想定損失、stress lossを表示する。
- **FR-UI-15** OANDA口座選択画面は全アクセス可能口座とpractice/live、通貨、hedging、margin、GSLO、MT4関連状態を表示する。
- **FR-UI-16** 自動口座選択ポリシーを使う場合、選択理由と除外理由を画面で説明する。

### イベントログ

- **FR-EVT-01** 市場データ、接続、戦略、リスク、注文、約定、システム、セキュリティのイベントを統一形式で保存する。
- **FR-EVT-02** 各イベントは重要度、カテゴリ、原因コード、メッセージ、構造化payload、発生元、対象、相関IDを持つ。
- **FR-EVT-03** 秘密値、認証ヘッダー、個人情報をpayloadへ保存しない。
- **FR-EVT-04** 同一処理のログ、シグナル、リスク判断、注文、約定を相関IDで追跡できる。
- **FR-EVT-05** 重大イベントはアプリ内通知を生成し、確認済み・未確認を管理する。

### 通知

- **FR-NOTIFY-01** 初期メール通知はGmail APIを使用する。
- **FR-NOTIFY-02** Gmail接続はOAuth 2.0 server-side flowを使用し、Googleアカウントの通常パスワードを受け取らない。
- **FR-NOTIFY-03** Gmail refresh tokenはSecret Managerへ保存し、DBにはsecret referenceと接続状態だけを保存する。
- **FR-NOTIFY-04** 通知内容にAPIキー、口座番号全文、内部例外、機密payloadを含めない。
- **FR-NOTIFY-05** 将来のメール・Slack等の追加に備え、通知provider interfaceをGmail固有処理から分離する。

### バックテスト

- **FR-BT-01** 対象期間、銘柄、時間足、戦略版、リスク設定版、手数料・スリッページを固定して実行する。
- **FR-BT-02** 実行時の入力条件とコード/イメージ版を保存し、再現可能にする。
- **FR-BT-03** 総損益、最大ドローダウン、勝率、Profit Factor、Sharpe相当値、取引一覧を出力する。
- **FR-BT-04** 未来情報の混入を防ぐ検証を自動テストする。

### AI学習・外部モデル

- **FR-ML-01** 利用者は対象市場、銘柄、期間、時間足、特徴量、予測対象、モデル種別、計算上限を指定して学習ジョブを作成できる。
- **FR-ML-02** 学習データのスナップショット、欠損状態、特徴量定義、コード版、乱数seed、ハイパーパラメータを保存する。
- **FR-ML-03** 時系列順序を保ったtrain/validation/test分割を使い、ランダムな行分割による未来情報混入を禁止する。
- **FR-ML-04** 学習済みモデルはバックテスト、手数料・スリッページ込み評価、paper観測を通過するまでBotへ適用できない。
- **FR-ML-05** アプリは許可された外部モデルカタログからメタデータを検索し、互換候補を提示できる。
- **FR-ML-06** 外部モデルを自動的に実取引へ使用してはならない。取得、隔離検査、互換性検査、再評価、人の承認を必須とする。
- **FR-ML-07** 外部モデルはライセンスが明示され、商用・改変・再配布条件が利用形態と一致するものだけを候補にできる。
- **FR-ML-08** 外部重みはsafetensors等の非実行形式を必須とし、pickle、任意Pythonコード、`trust_remote_code` を禁止する。
- **FR-ML-09** モデルはリポジトリ名だけでなくrevision/commitとSHA-256を固定し、後日の差し替えを防ぐ。
- **FR-ML-10** 外部モデルが高性能かどうかは名称や公開スコアではなく、本アプリの同一ホールドアウトデータと損益・DD指標で判定する。
- **FR-ML-11** 学習ジョブはCPU/GPU、メモリ、実行時間、同時実行数を制限し、取引ワーカーと計算資源を分離する。
- **FR-ML-12** 学習・探索・ダウンロード・検査・評価・承認・配備をイベントログへ記録する。

## 5. 主要業務ルール

- 保存時刻はUTC、APIはRFC 3339、画面表示は利用者設定へ変換する。
- 金額と数量は銘柄ごとのtick size、step size、最小注文額に丸める。
- シグナルは注文ではない。リスク承認された注文意図のみ執行対象になる。
- ポジションと残高の正本は、ペーパーでは内部台帳、実取引では取引所照合結果とする。
- 市場データが規定時間以上遅延した場合、新規ポジションを禁止する。
- 停止は最小範囲へ適用する。ただし認証侵害、台帳不整合、緊急停止はworkspaceまたはsystem全体へ拡大できる。
- AIモデルとテクニカル指標の結果を暗黙に混合しない。
- Binance BTC/JPYでは借入、空売り、レバレッジ、デリバティブを初期版で禁止する。
- OANDA USD/JPYでは口座レバレッジにかかわらず、アプリ独自の実効レバレッジ上限を適用する。
- ユーザー設定はbroker制約を緩和できず、アプリのsystem hard limitを超えられない。
- 確定済みローソク足は原則不変とし、訂正時は更新元と更新時刻を監査する。
- 戦略、リスク設定、モデルは必ず版を固定して実行する。

## 6. 非機能要件

| ID | 分類 | 要件 |

| NFR-01 | 安全性 | 外部API障害、DB障害、データ異常時は新規注文を停止する |
| NFR-02 | セキュリティ | TLS、秘密管理基盤、最小権限、監査ログ、依存関係スキャンを適用する |
| NFR-03 | 可用性 | MVP目標99.5%。再起動後にBot状態とポジションを復元できる |
| NFR-04 | 性能 | 通常の履歴API p95 500ms以内。重い指標計算は非同期またはキャッシュする |
| NFR-05 | 整合性 | 注文・約定・台帳更新はトランザクションまたは再試行可能なイベント処理とする |
| NFR-06 | 監視 | 構造化ログ、メトリクス、トレース相関ID、重大アラートを備える |
| NFR-07 | テスト | ドメインロジック80%以上を目安にし、金額計算・状態遷移は網羅する |
| NFR-08 | 保守性 | 取引所アダプターをドメインから分離し、契約テストを持つ |
| NFR-09 | データ | 日次バックアップと復元訓練。監査記録は追記専用とする |
| NFR-10 | 説明可能性 | シグナルとリスク拒否を保存データから説明できる |

## 7. MVP受入条件

1. 無効または未設定の秘密情報がログ・APIレスポンスに現れない。
2. 24時間の連続ペーパー運転で、重複注文・重複約定が発生しない。
3. WebSocket切断、欠損、RESTエラー、DB一時障害の試験で影響Botの新規注文が安全に停止し、無関係なBotは継続する。
4. 同じ履歴・戦略版・設定版から同じシグナルとバックテスト結果が得られる。
5. すべての注文について、元シグナル、リスク判断、約定、残高変化を追跡できる。
6. プロセス再起動後も口座、ポジション、Bot状態が復元される。
7. 権限のない利用者が設定変更、Bot操作、秘密情報操作を行えない。
8. 主要状態遷移・金額計算・取引所アダプター契約の自動テストが成功する。
9. 外貨FXと仮想通貨FXのBotを同時にペーパー運転し、状態・注文・イベントが混同されない。
10. technical/ai_modelのモード切替が停止中かつ新設定版の適用時にのみ行える。
11. OANDA USD/JPYとBinance BTC/JPY spotの成行・指値注文をpaperで再現し、注文状態を追跡できる。
12. 外部モデル候補は安全検査・ライセンス・互換性・再評価・承認のいずれかが未完了なら配備できない。
13. 同一アルゴリズム版・入力snapshotから同一シグナルを再現できる。
14. リスク値を変更しても稼働中Botへ直接反映されず、承認済み版の再配備が必要になる。
15. 1つのOANDAトークンで参照可能な複数v20口座を列挙し、手動・ポリシー選択の結果を説明できる。
