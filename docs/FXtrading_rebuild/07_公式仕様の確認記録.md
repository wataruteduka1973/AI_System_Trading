# 公式仕様の確認記録

**最終確認日: 2026-08-16**

外部サービスの提供商品、銘柄、注文種別、制限は変更される可能性がある。本記録は設計根拠であり、アプリケーションは接続時および定期的にAPIから実際のcapabilitiesを取得して再確認する。

## OANDA

- [OANDA REST v20 Order definitions](https://developer.oanda.com/rest-live-v20/order-df/)
- [OANDA REST v20 Order endpoints](https://developer.oanda.com/rest-live-v20/order-ep/)
- [OANDA REST v20 Account definitions](https://developer.oanda.com/rest-live-v20/account-df/)
- [OANDA REST v20 Account endpoints](https://developer.oanda.com/rest-live-v20/account-ep/)
- [OANDA REST v20 Development Guide](https://developer.oanda.com/rest-live-v20/development-guide/)
- [OANDA Margin rules](https://help.oanda.com/us/en/faqs/margin-rules.htm)
- [OANDA Stop-loss education](https://www.oanda.com/us-en/skills-and-insights/education/introduction-trading/first-trade/where-to-put-your-stop-loss/)
- [OANDA Trading strategies education](https://www.oanda.com/us-en/skills-and-insights/education/trading-strategies/)

確認事項:

- MarketOrderRequestとLimitOrderRequestが定義されている。
- Market注文はFOK/IOC、Limit注文は価格と有効期間を扱う。
- stop-loss、take-profit、guaranteed stop-loss、trailing stop-loss等の関連注文が定義されている。
- 実際に利用可能な商品、精度、保証ストップ対応等は接続した口座のAPI応答から判定する。
- トークンからアクセス可能な口座一覧と各口座詳細をAPIで取得できる。
- 口座詳細にはhedgingEnabled、marginRate、marginAvailable、marginCallPercent、marginCloseoutPercent、保証ストップモード等が含まれる。
- practice/liveは接続先endpointが異なるため、アプリでも別接続として管理する。
- アプリは利用口座を選べるが、OANDAが持つ口座方式そのものを任意に変換できるわけではない。
- OANDAは各open tradeへのstop-loss設定とmargin状態の継続監視をリスク低減策として案内している。
- OANDA教育資料には1% risk ruleが紹介される一方、stop位置はリスク管理と戦略等の複数要因を考慮すべきとされている。このため本設計では1%を普遍的推奨値とはせず、初期値を0.5%へ保守化した。
- stop-lossは指定価格での約定を保証せず、gapや市場再開時には超過損失が生じ得る。

## Binance

- [Binance Spot REST API — exchangeInfo](https://developers.binance.info/en/docs/catalog/core-trading-spot-trading/api/rest-api)
- [Binance Spot API official repository](https://github.com/binance/binance-spot-api-docs)

確認事項:

- `/api/v3/exchangeInfo` が取引中のsymbol、orderTypes、価格・数量filter、permissionsを返す。
- MARKET/LIMITを含む注文種別は銘柄ごとの応答を正本とする。
- `BTCJPY` を設定値だけで利用可能と仮定せず、接続先のexchangeInfoで `status=TRADING`、SPOT権限、必要なorderTypesを確認する。
- 初期版はSpot Testnetまたはpaperから検証し、margin・leveraged・derivativesを拒否する。

## Hugging Face Hub

- [Hub API endpoints](https://huggingface.co/docs/hub/en/api)
- [Hub security](https://huggingface.co/docs/hub/security)
- [Pickle scanning](https://huggingface.co/docs/hub/security-pickle)
- [Safe serialization](https://huggingface.co/docs/huggingface_hub/package_reference/serialization)

確認事項:

- Hub APIと公式クライアントでモデルメタデータを検索できる。
- Hubはマルウェア・pickle等のscan機能を提供するが、scanは完全な安全保証ではない。
- pickleはロード時に任意コード実行へつながる危険があり、safetensorsが推奨される。
- 本アプリではHubのscanだけに依存せず、safetensors限定、revision固定、checksum、隔離、ライセンス審査、独自評価を必須とする。

## FastAPI

- [FastAPI Features](https://fastapi.tiangolo.com/features/)
- [FastAPI async/concurrency](https://fastapi.tiangolo.com/async/)
- [FastAPI deployment concepts](https://fastapi.tiangolo.com/deployment/concepts/)

確認事項:

- OpenAPI/JSON Schema、型検証、WebSocketを標準的に扱える。
- 外部API・DB待ちが多い処理にはasync I/Oを利用できる。
- CPU負荷の高いMLは別process/workerへ分離でき、APIは複数workerで拡張可能。

## Gmail

- [Gmail API sending guide](https://developers.google.com/workspace/gmail/api/guides/sending)
- [Gmail server-side OAuth](https://developers.google.com/workspace/gmail/api/auth/web-server)

確認事項:

- Gmail APIはmessages.sendでメールを送信できる。
- server-side applicationはOAuth 2.0のauthorization codeとrefresh tokenを使用できる。
- 本アプリはGoogleアカウントの通常パスワードやApp Passwordを保存せず、OAuthを採用する。
