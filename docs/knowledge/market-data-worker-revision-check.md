# 市場データ Worker が約2週間起動していなかった(2026-09-20 〜 2026-10-03)

## 何が起きたか

市場データ Worker(`python -m app.market_data.worker`)は、起動時に DB のリビジョンが
`20260831_0005` と完全に一致することを求めていた。その後マイグレーションが追加される
たびに(最初は 2026-09-20 の 0006)、正しく最新まで適用された DB に対しても起動を拒否した。
エラーは「`alembic upgrade head` を実行せよ」と案内したが、DB は既に最新なので従っても直らない。

起動スクリプト(`scripts/start_local.py`)は市場データ Worker を「止まっても API と画面は
続ける」非必須プロセスとして扱うため、画面は普通に動き、気付かれなかった。
Testnet/Practice のローソク足の自動収集とバックフィルが止まっていた。ペーパートレードの
ボットはトレーディング Worker が公開価格を自分で取り込むので影響を受けなかった。

## 直したこと

必要なリビジョンを固定値ではなく、コードと一緒にある `alembic/versions` の head から
起動時に読む(`_required_revisions`)。「コードが知っているスキーマと完全に一致したときだけ
動く」という元の設計意図(古い DB でも新しすぎる DB でも動かない)はそのまま。
回帰テスト: `tests/test_worker_main.py` の
`test_check_schema_revision_accepts_a_database_at_the_codes_latest_migration`。

## 次に同じことを避けるために

- DB のリビジョンを確認するコードに、リビジョン ID を直接書かない。基準はコードと一緒にある
  マイグレーションの head にする。
- 起動ウィンドウの状態表示で、Worker が「停止(要確認、[A]で再起動)」になっていないかを
  確認する。非必須プロセスの停止は、画面からは分からない。
- マイグレーションを追加した PR では、市場データ Worker が起動することまで確認する。
