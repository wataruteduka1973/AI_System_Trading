# DB から読んだ時刻はUTCとは限らない

## 何が起きたか

PostgreSQL の `timestamptz` 列は、接続のタイムゾーン(この環境では日本時間)に変換されて返る。
`datetime` 自体はタイムゾーン付きで正しい時刻を指すが、`f"{t:%H:%M}"` のように書式化すると
日本時間の数字になる。

`scripts/check_paper_parity.py` は足や約定の時刻をそのまま表示していたため、「評価されなかった足」が
日本時間で表示され、UTC と読み違えた(2026-10-03 の報告で、21:00 / 1:00 / 5:00 を UTC として伝えた。
実際は日本時間)。2026-10-05 に `report_paper_performance.py` を作ったときも同じ誤りを入れかけた。

## 守ること

- 時刻を表示・比較する前に `.astimezone(UTC)` で UTC にそろえる。足は UTC の時間足の倍数
  (4h なら 0/4/8/12/16/20 時 UTC)で区切られているので、UTC で見ないと区切りが合わない。
- 表示に「UTC」と書くなら、その値を必ず UTC に変換してから書式化する。
- 比較(`<=` など)はタイムゾーン付き同士なら正しく動くので、変換が必要なのは表示のとき。
